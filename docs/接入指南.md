# 接入指南

编辑器有三种接法，可以混用：业务系统的后端用 REST API 建模板、建合同、出文件；前端用 SDK 或 iframe 把编辑器放进自己的页面。

| 接法 | 适合 | 入口 |
| --- | --- | --- |
| REST API | 所有系统的后端（Java、.NET、Go、PHP、Node） | `apps/server`，`/api/*` |
| SDK | 用 npm 打包的前端（Vue、React、Angular 都行） | `@oe/web` 的 `createEditor` |
| iframe 嵌入 | 任何网页，包括 JSP、ASP.NET、PHP 页面 | 嵌入页 `embed.html` + `@oe/web/embed` 的 `connectEmbed` |

## 1. 鉴权

- 业务系统后端：`Authorization: Bearer <API Key>`。API Key 只放在后端，不下发浏览器。
- 浏览器：后端用 API Key 调 `POST /api/tokens` 签一个短时效的文档令牌，前端放在请求头 `X-Document-Token`。令牌绑定文档、模式、用户、字段权限、能不能打印下载，随时可以改权限或吊销。
- 令牌和登录态都不放进任何地址（包括 iframe 的 `src`）。

## 2. REST API

常用接口（完整入参看 `apps/server/src/app.ts` 里各接口的 zod 定义）：

| 接口 | 作用 |
| --- | --- |
| `PUT /api/field-library` | 登记业务字段库（字段 key、名称、类型、数据源、带出关系） |
| `POST /api/templates` | 建模板：`doc`（文档 JSON）或 `docx`（base64，自动转换，返回导入报告） |
| `POST /api/templates/{id}/versions` | 发布新版本（已发布的版本不可改） |
| `POST /api/documents` | 用模板版本 + `values` 建合同 |
| `GET /api/documents/{id}` | 取文档、字段值、状态、版本号 |
| `PATCH /api/documents/{id}/data` | 合并更新字段值 |
| `POST /api/documents/{id}/operations` | 批量操作（插入、替换、改条款、填值），原子执行 |
| `GET /api/documents/{id}/export?format=pdf\|docx\|html\|txt` | 下载；`&version=` 指定版本，对不上返回 409 |
| `POST /api/render` | 模板版本 + 数据直接出文件（`format` 同上），不建合同 |
| `POST /api/convert` | 格式转换，不落库：`docx` → `json`（文档 + 导入报告）/ `pdf` / `docx` / `html` / `txt`；`doc`（文档 JSON）→ `pdf` / `docx` / `html` / `txt` |
| `POST /api/tokens` | 签发文档令牌；`userName` 是在场、批注、修订、编辑锁里显示的名字 |
| `POST /api/documents/{id}/seal-status` | 开始盖章、提交、驳回、作废；还有没处理的修订时不能开始（422 `PENDING_REVISIONS`） |
| `GET /api/documents/{id}/events` | 多人编辑的事件流（SSE），见第 7 节 |
| `POST /api/documents/{id}/presence`、`/lock` | 报在场的字段；正文编辑锁 |
| `/api/documents/{id}/comments` | 批注：GET 列表、POST 加，`/comments/{cid}` 上 PATCH 解决或改、DELETE 删 |
| `GET /api/documents/{id}/revisions`、`/revisions/{version}` | 版本列表、某一版的内容（版本对比用） |

例：把一份 Word 合同转成 PDF。

```bash
curl -X POST https://editor.example.com/api/convert \
  -H "Authorization: Bearer $API_KEY" -H "Content-Type: application/json" \
  -d "{\"docx\":\"$(base64 -w0 合同.docx)\",\"to\":\"pdf\",\"title\":\"设备采购合同\"}" \
  -o 设备采购合同.pdf
```

例：订单审批通过后出正式合同。

```text
POST /api/documents          { templateId, versionNo, bizKey: "订单号", values: { contractNo, amount, items } }
POST /api/tokens             { documentId, mode: "fill", userId, permissions: { amount: "readonly" } }   → 给业务员填写
POST /api/documents/{id}/seal-status  { action: "start", version }                                         → 进入盖章
GET  /api/documents/{id}/export?format=pdf&version=8                                                      → 归档
```

## 3. SDK（npm 打包的前端）

```ts
import { createEditor } from '@oe/web'

const editor = await createEditor(document.querySelector('#editor')!, {
  mode: 'fill',
  load: async () => (await fetch('/my-backend/contract/123')).json(), // 后端用文档令牌取 GET /api/documents/{id}
  save: async (payload) => { await fetch('/my-backend/contract/123', { method: 'PATCH', body: JSON.stringify(payload) }) },
  request: async ({ url, method, query, body }) => myHttp(url, { method, query, body }), // 远程数据源带自己的登录态
  download: async (format) => { location.href = `/my-backend/contract/123/export?format=${format}` }, // 可选：PDF、Word 走服务端
})

editor.on('field-change', ({ key, value }) => console.log(key, value))
editor.setData({ contractNo: 'HT-2026-0001' })
const blob = await editor.export('docx') // 浏览器里生成，不经服务端
```

句柄的方法：`getData`、`setData`、`validate`、`save`、`isDirty`、`setMode`、`apply`（批量操作）、`find`、`insertText`、`insertField`、`getText`、`export`、`download`、`import`、`print`、`focus`、`on` / `off`、`destroy`。

事件：`ready`、`change`（用户改了内容）、`field-change`（字段值变了）、`saved`、`mode-change`、`dirty-change`、`field-focus`。

## 4. iframe 嵌入（任何网页）

1. 部署嵌入页（`apps/demo/embed.html` 构建后的产物，或自己照 `apps/demo/src/embed.ts` 写一页），比如在 `https://editor.example.com/embed.html`。
2. 业务系统页面里放 iframe，地址上用 `origin` 写自己页面的来源（嵌入页只认这些来源，可写多个，逗号分隔）：

```html
<iframe id="editor" src="https://editor.example.com/embed.html?origin=https://oa.example.com"></iframe>
```

3. 用 `@oe/web/embed` 的 `connectEmbed`（不带 Vue，几 KB）把文档交给编辑器，实现要用的宿主函数：

```ts
import { connectEmbed } from '@oe/web/embed'

const editor = await connectEmbed(document.querySelector('#editor'), {
  origin: 'https://editor.example.com',          // 只认这个来源发来的消息
  mode: 'fill',
  document: await (await fetch('/oa/contract/123')).json(),   // { doc, fields, values, title, permissions, actions }
  host: {
    save: async (payload) => { await fetch('/oa/contract/123', { method: 'PATCH', body: JSON.stringify(payload) }) },
    request: async (req) => oaHttp(req),          // 远程数据源：在父页面发，带 OA 的登录态
    search: async (field, query, page) => ({ items: [], total: 0, pageSize: 5 }),
  },
})

editor.on('dirty-change', (dirty) => { window.onbeforeunload = dirty ? () => true : null })
await editor.setData({ contractNo: 'HT-2026-0001' })
const pdf = await editor.export('pdf')           // Blob
```

方法、事件和 SDK 一样，只是都返回 Promise。宿主函数可以实现 `save`、`publish`、`search`、`request`、`download`、`importDocx`、`onSeal`，没实现的就不用。

安全约定：

- 嵌入页只处理 `origin` 参数里列出的来源发来的消息，第一次初始化之后只认那一个来源；回消息时指定目标来源。
- 客户端只处理这个 iframe 发来的、来源是 `origin` 的消息。
- 文档令牌和登录态不进 iframe 地址；保存、搜索这些在父页面执行。

示例：`pnpm --filter @oe/demo dev` 后打开 `http://localhost:5173/embed-host.html`，左边是一个不用 Vue 的「业务系统」页面，右边 iframe 里是编辑器。

## 5. 文件格式

| 格式 | 浏览器里打开 | 浏览器里下载 | 服务端 |
| --- | --- | --- | --- |
| Word（.docx） | 有（带导入报告） | 有 | 导入（建模板、`/api/convert`）、导出 |
| PDF | — | 有（图片版，不能选字） | 有（带文字层，正式件用这个） |
| HTML | 有（清洗掉脚本、事件属性） | 有 | 有 |
| Markdown | 有 | — | — |
| 纯文本 | 有 | 有 | 有 |
| JSON（文档 + 字段 + 值） | 有 | 有（编辑模式） | `GET /api/documents/{id}` |
| 图片（每页一张 PNG） | — | 有（zip） | — |

令牌关了下载时，界面上没有下载项，服务端 `/export` 返回 403；打印同理。

复选、单选在 Word、HTML、纯文本里写成「☑ 选中的 ☐ 没选的」，SDK 的 `getText` 也一样；PDF、图片照编辑器画。

## 6. 字段值

`values`（REST API 建合同、改值）、`setData` 和 `getData().values.values` 用同一种写法，键是字段 key：

| 字段类型 | 值 | 例 |
| --- | --- | --- |
| 文本、数字、金额 | 字符串 | `"HT-2026-0001"`、`"5200"` |
| 日期 | 显示的文字，按字段的日期格式 | `"2026年11月05日"` |
| 下拉、单选 | 选项的 code（写的时候也认选项文字） | `"stage"` |
| 复选 | 选中的 code 用逗号连起来；写的时候也认数组 | `"ac,parking"`、`["ac", "parking"]` |
| 数据选择 | 显示的文字；带出的字段各有各的值，选中的记录在 `snapshots` 里 | `"苏州工业园区精工机械有限公司"` |
| 表格循环 | 数组，一行一个对象，键是列名 | `[{ "name": "显示器", "qty": "2" }]` |
| 图片 | 图片的 dataURL | `"data:image/png;base64,…"` |
| 计算（金额大写、公式） | 不用传，按来源字段、公式算 | `"伍仟贰佰元整"`、`"36000"` |
| 签名区 | 签名图片的 dataURL；`null` 换回占位图 | `"data:image/png;base64,…"` |
| 签署日期 | 显示的文字，按字段的日期格式 | `"2026年11月05日"` |

演示里的 5 份范本（`apps/demo/src/samples.ts`）是现成的写法：字段定义、文档 JSON、样例值都在里面。销售合同有公式和条件条款，保密协议有签名区、签署日期和校验规则。

### 公式

```json
{ "key": "products", "label": "产品明细", "type": "loop", "loop": { "columns": ["name", "qty", "price", "amount"], "formulas": { "amount": "qty * price" } } }
{ "key": "total", "label": "总价", "type": "computed", "computed": { "fn": "formula", "expr": "sum(products.amount)", "digits": 2 } }
{ "key": "totalCN", "label": "总价大写", "type": "computed", "computed": { "fn": "amountCN", "from": "total" } }
```

- 写法：数字、字段 key、`+ - * /`、括号；`sum(循环字段.列)` 是那一列所有行的合计。循环表的行内公式（`loop.formulas`：列名 → 公式）只引用同一行的列，按写的顺序算。没有别的函数，不执行脚本。
- 引用的值空着时结果是空，除以 0 也是空。值里的千分位逗号、空格、￥ 不算。`digits` 是保留几位小数（0～6，默认 2），末尾的 0 去掉（`5200`、`0.33`）。计算字段可以引用别的计算字段，按依赖顺序算。
- 浏览器和服务端用同一套代码（`@oe/core` 的 `computeValues`）：建合同、改值时服务端重算。计算字段不能写：建合同时传了不用，`PATCH`、批量操作返回 403 `PERMISSION_DENIED`；行内公式的列传了也按公式重算，编辑器里是灰的。
- 建模板、登记字段库时服务端查公式：写错、引用不存在的字段、`sum` 的不是循环字段的列、循环引用，都返回 400。

### 校验规则

```json
{ "key": "contactPhone", "label": "联系电话", "type": "text", "rules": { "pattern": "mobile" } }
{ "key": "penalty", "label": "违约金", "type": "amount", "rules": { "min": 0, "max": 10000000 } }
```

| 规则 | 含义 |
| --- | --- |
| `minLength`、`maxLength` | 字数（按字符算） |
| `pattern` | `mobile` 手机号、`idCard` 18 位身份证号（查出生日期和校验位）、`creditCode` 统一社会信用代码（按 GB 32100 查字符和校验位）、`email` 邮箱 |
| `min`、`max` | 数值范围，值要是数字 |

- 值空着不查，要必填用权限 `required`。不收自定义正则：服务端要拿它去匹配别人填的值，写坏的正则会拖住服务端。
- 编辑器：填写模式离开字段时，不合规的在字段列表里标出原因；提交时拦住，保存状态写哪一项、为什么；SDK 的 `validate()` 把它们放在 `invalid` 里。只查填写的人能改的字段。接了 `collab` 时，自动保存先不交不合规的字段。
- 服务端：建合同、`PATCH /data`、批量操作的 `setData`、`/api/render` 写值前都查，有一个不合规整次拒绝，`code` 是 `INVALID_VALUE`，`message` 写哪个字段、为什么；批量操作返回 422（带 `index`），其余 400。编辑模式整份保存（PUT）不查，那是起草。
- 规则写错（下限大于上限、不认识的 `pattern`、别的键）时，建模板、登记字段库返回 400。

### 条件条款

文档 JSON 里是一个区域，条件写在 `area.extension.when`：

```json
{ "type": "area", "value": "", "area": { "extension": { "when": { "field": "payMethod", "in": ["stage"] } } }, "valueList": [{ "value": "分期付款的，买方于……" }] }
```

- 字段的值是 `in` 里的一个时才出这段，按选项的 code 比；复选有一个选中的在里面就算；值空着不出。编辑器里用格式栏的「条件条款」：选中一段正文，选一个下拉、单选或复选字段和它的选项。
- 服务端每次写值、保存（建合同、`PATCH`、`PUT`、批量操作）都按现在的值重算 `area.hide`，存下的文档里 `hide` 就是对的。PDF、Word、HTML、纯文本，编辑器的填写、盖章、只读模式都按它出；编辑模式里条件条款都显示（浅灰底），导出照样按值。
- 条件条款不能用来藏机密：令牌拿到的文档里它的内容还在（值一变就要显示）。要对某些人保密的内容放进 `hidden` 权限的字段。
- 宿主自己处理文档 JSON 时，`@oe/core` 的 `applyConditions(doc, values)` 按值设好 `hide`，`withoutHiddenAreas(doc)` 去掉隐藏的区域（HTML、纯文本导出前用）。

### 签名区、签署日期

```json
{ "key": "signA", "label": "甲方签名", "type": "signature", "signer": "a" }
{ "key": "signDateA", "label": "甲方签署日期", "type": "signDate", "signer": "a", "format": "yyyy年MM月dd日" }
```

- `signer` 是签署方角色：编辑器预设 `a`～`d`（甲方、乙方、丙方、丁方）；字段库里的 `signer` 要以小写字母开头，只用小写字母、数字、`_`、`-`，最长 32 位。
- 签名区在文档里是图片：`{ "type": "image", "value": "<占位图>", "width": 160, "height": 56, "extension": { "field": "signA", "signer": "a", "placeholder": "<占位图>" } }`。没签时显示占位图（一道浅灰线，上面写字段名）；值写 `null` 时服务端换回 `extension.placeholder`。服务端画不了图，宿主自己拼文档时要带上占位图；在浏览器里可以用 `@oe/web` 的 `fieldElement(field, 正文宽度)` 生成，和编辑器插入的一样。
- 签署日期是只读的文字控件，值按字段的日期格式写。
- 两种字段默认只读，也不在填写模式的字段列表里：宿主用 API Key 写（建合同的 `values`、`PATCH`、批量操作的 `setData`），或者签令牌时在 `permissions` 里给 `editable`。
- 签名区放的是签名图片，不是数字签名。

## 7. 多人编辑、批注、修订、版本

正文同一时间一个人编辑（编辑锁），字段和可编辑区可以多人同时填；不是逐字实时合写。

### 前端：接上事件流

SDK 的 `collab` 传 `@oe/web` 的 `sseCollab`，每个地址都对着服务端，令牌放请求头（不进地址）。哪一项不给就没有对应的功能：

```ts
import { createEditor, sseCollab } from '@oe/web'

const base = `/api/documents/${id}`
const headers = { 'X-Document-Token': token }
const editor = await createEditor(el, {
  mode: 'edit',
  load, save, // save 见下面
  collab: sseCollab({
    events: `${base}/events`,       // 在场、别人保存的字段和正文、编辑锁、状态、批注变了
    presence: `${base}/presence`,   // 告诉别人自己在哪个字段
    lock: `${base}/lock`,           // 正文编辑锁
    document: base,                 // 别人保存了正文后重新取
    comments: `${base}/comments`,   // 批注
    revisions: `${base}/revisions`, // 版本历史和对比
    headers,
  }),
})
```

接了 `collab` 以后，编辑器停一会儿就自动保存（填写 1.5 秒；编辑模式拿着锁时 3 秒），交给 `save` 的 `payload` 多了几项，宿主原样转给服务端：

| payload | 交给服务端 | 说明 |
| --- | --- | --- |
| `version` | PUT、PATCH 的 `version` | 编辑器手上的文档是哪一版 |
| `base` | PUT、PATCH 的 `base` | 每个改过的字段（可编辑区是 `area:anchor`）编辑器看到的是哪一版 |
| `conn` | PUT、PATCH 的 `conn` | 自己的事件流连接，服务端推改动时不推回来 |
| `changed` | PATCH 的 `patch` 只放这几个字段 | 不放的字段不会被旧值盖掉 |

`save` 返回服务端的结果，编辑器按它处理：

| 服务端 | `save` 返回 | 编辑器 |
| --- | --- | --- |
| 200 | `{ version }` | 记下版本 |
| 409 `FIELD_CONFLICT`（带 `conflicts`、`version`） | `{ conflicts, version }` | 这次没保存；那几项换成对方的值，提示「李四先改了…」，其余的接着保存 |
| 409 `VERSION_CONFLICT`（带了 `base` 时） | `{ stale: true }` | 正文被别人整份改过：填写的先按最新的重新装再保存；编辑的提示刷新 |
| 423 `LOCKED` | 抛错 | 别人拿着编辑锁 |

现成的写法见 `apps/demo/src/server-host.ts`。

### 服务端：接口

- 事件流 `GET /api/documents/{id}/events?since=<版本号>`：`text/event-stream`。先发 `hello`（自己的连接 id、名字、版本号、状态、编辑锁；带了 `since` 时补发这之后别人改的字段），之后有 `presence`、`fields`、`doc`、`lock`、`lock-request`、`status`、`comments`；25 秒一个心跳注释；令牌过期、被吊销或改了权限时服务端断开，客户端重连时重新鉴权。每个连接只收到它看得到的字段。
- 字段合并：PUT、PATCH 带 `base` 才按字段合并（别人改的是别的字段就合并，同一字段在基准之后被别人改过就 409 `FIELD_CONFLICT`，先保存的算数）；不带 `base` 和以前一样严格比版本号，不用多人编辑的宿主不受影响。
- 编辑锁 `POST /lock` `{ conn, action: 'acquire' | 'release' | 'request', to? }`：只有编辑模式的令牌（和宿主）能用；挂在事件流连接上，连接断了就放掉，120 秒没续约算过期（编辑器 30 秒续一次）；`release` 带 `to` 时直接交给请求的人。别人拿着锁时 PUT 返回 423；没人拿锁时照旧。开始盖章、作废时锁一起放掉。
- 批注：单独存，不进文档 JSON、不进导出。盖章模式不能写，作废的文档不能写；只能改、删自己的（宿主都能）；回复挂在最上面那条下面。
- 版本：建文档、编辑模式保存（PUT）、改了正文的批量操作、每次状态变化各存一份；同一个人 10 分钟内连着编辑只留最后一份，填写保存不单独存。列表返回 `{ version, reason, operatorName, at }`，`reason` 是 `create`、`edit`、`start`、`submit`、`reject`、`void`；内容按令牌现在的权限剔除隐藏字段的值。盖章模式的令牌不能看。

### 修订

文档 JSON 的 `trackChanges: true` 表示记录修订开着；被插入、删除的元素带 `trace: [{ type: 'inserted' | 'deleted', author, timestamp }]`，删除的元素还在 JSON 里（编辑器不画）。宿主改文档 JSON 时注意：

- 取文字、比对内容时跳过最后一条是 `deleted` 的元素，或者先用 `@oe/core` 的 `resolveTraces(doc, 'accept')` 得到全部接受后的样子；`traceChanges(doc)` 列出每一处修订。
- 导出（PDF、Word、HTML、纯文本）都按全部接受后的样子。
- 还有没处理的修订时 `seal-status` 的 `start` 返回 422 `PENDING_REVISIONS`：先在编辑器里接受或拒绝。
